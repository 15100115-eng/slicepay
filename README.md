# SlicePay

SlicePay არის „იყიდე ახლა, გადაიხადე ნაწილ-ნაწილ“ სერვისის მუშა პროტოტიპი: მომხმარებელი უცხოური მაღაზიის
(Amazon, eBay …) პროდუქტის ბმულს ჩასვამს, ხედავს სრულ ფასს (პროდუქტი, ტრანსპორტირება, განბაჟება,
მიწოდება), ირჩევს ბანკს და ვადას, და იხდის პირველ შენატანს. შემდეგ თვალს ადევნებს შეკვეთას „ჩემ შეკვეთებში“,
ხოლო „პროფილში“ არედაქტირებს საკუთარ მონაცემებს, ტელეფონის ნომერს და პაროლს.

პროტოტიპი აწყობილია Figma-ს დიზაინიდან ორ ზომაზე: მობილური 428×735
და დესკტოპი 1440×1024. ინტერფეისი ქართულია. ის არის სუფთა HTML/CSS/vanilla JS: არ აქვს build ნაბიჯი,
ფრეიმვორკი ან ბიბლიოთეკა, არ აკეთებს ქსელურ მოთხოვნას, და იხსნება პირდაპირ `file://`-დან.

**ონლაინ ვერსია:** https://15100115-eng.github.io/slicepay/ (GitHub Pages; ყველა მონაცემი სატესტოა და მხოლოდ ბრაუზერში ინახება)

## How to open

- **უბრალოდ:** ორჯერ დააწკაპუნეთ `index.html`-ზე (გაიხსნება ბრაუზერში `file://`-დან).
- **ლოკალური სერვერით:** `npm run serve` → <http://127.0.0.1:8765/> (სურვილისამებრ პორტი: `node tools/serve.js 9000`).
  Claude Code-ის preview იყენებს იმავე სერვერს (`.claude/launch.json`).

## Profile (v4)

`#/profile` საჭიროებს ავტორიზაციას (სხვა შემთხვევაში → `#/login?next=/profile`). შესასვლელი: დესკტოპის ჰედერში
`პროფილი` · `ჩემი შეკვეთები`, ასევე „ჩემი შეკვეთების“ სათაურის ბმული `პროფილი`. გასვლა (`ᲒᲐᲡᲕᲚᲐ`) ახლა მხოლოდ
პროფილის გვერდზეა.

- **პირადი ინფორმაცია** — სახელი, გვარი, ელ.პოსტა; `ᲨᲔᲜᲐᲮᲕᲐ` აქტიურდება ცვლილების შემდეგ. ინახება ანგარიშზე
  (localStorage), ამიტომ მიწოდების ფორმაში მიმღების სახელი/გვარი პროფილიდან ივსება (ამ სესიაში აკრეფილი მნიშვნელობა
  უპირატესია). ბარათის მონაცემები არსად ინახება; პირადი ნომერი localStorage-ში არ ინახება — მხოლოდ ამ ჩანართის
  სესიაში (sessionStorage), შეკვეთაში კი მხოლოდ დაფარული სახით (`********345`).
- **ტელეფონის ნომერი** — `ნომრის შეცვლა` → ახალი ნომერი → `ᲙᲝᲓᲘᲡ ᲒᲐᲛᲝᲒᲖᲐᲕᲜᲐ` → SMS კოდი (ჩანს შეტყობინებაში;
  ხელახლა გამოგზავნა 30 წამში ერთხელ, კოდი მოქმედებს 5 წუთი) → `ᲓᲐᲓᲐᲡᲢᲣᲠᲔᲑᲐ`. წარმატების შემდეგ ანგარიში, მისი
  შეკვეთები, „დამახსოვრება“ და მიმდინარე სესია გადადის ახალ ნომერზე; ძველი ნომერი თავისუფლდება. იმავე ანგარიშით
  ღიად დარჩენილ სხვა ჩანართებში სესია სრულდება (შეტყობინება + შესვლის გვერდი). სესია მიბმულია თავად ანგარიშზე და არა
  ნომერზე: დახურული და აღდგენილი ან აპიდან გასული ჩანართიც, რომელიც დაბრუნდება, როცა ძველი ნომერი უკვე სხვას
  ეკუთვნის, შესვლის გვერდზე აღმოჩნდება — სხვის ანგარიშში არასოდეს. ასეთი სესია არც შეკვეთას ჩაწერს და არც პროფილს
  შეცვლის.
- **პაროლის შეცვლა** — მიმდინარე, ახალი (მინ. 8 სიმბოლო) და გამეორება. „ახალი პაროლი ემთხვევა მიმდინარეს“
  მოწმდება მხოლოდ სწორი მიმდინარე პაროლის შემდეგ.

## Order statuses

შეკვეთის სტატუსები თანმიმდევრობით (v4-დან პირველია „მუშავდება“):

`მუშავდება` → `შეკვეთილია` → `გზაშია` → `საწყობშია` → `განბაჟება` → `მზადაა გასატანად` | `კურიერთანაა` → `ჩაბარდა`

- **მუშავდება** — SlicePay ამუშავებს შეკვეთას (ბანკის დადასტურება და მაღაზიაში შეკვეთის განთავსება). ყოველი ახალი
  შეკვეთა ამ სტატუსით იწყება; სიაში ჩანს იისფერი „მიმდინარე“ ნიშნით.
- დემო შეკვეთებს (#548210, #731954) აქვთ „მუშავდება“ ნაბიჯი შეკვეთის თარიღით. ძველ, ბრაუზერში უკვე შენახულ
  შეკვეთებს ეს ნაბიჯი ავტომატურად ემატება (შესრულებულად, შეკვეთის თარიღით) და თავიანთ სტატუსს ინარჩუნებენ.

## QA URL params

პარამეტრები ემატება hash-ს, მაგ. `index.html#/cart?demo=1&details=1`. ხშირად გამოყენებადი:

| პარამეტრი | რას აკეთებს |
|---|---|
| `demo=1` | დემო პროდუქტი (Nike), დემო მომხმარებელი შესულია, დასრულებული მიწოდება; `#/orders`-ზე — ორი დემო შეკვეთა (#548210, #731954) |
| `weight=0\|1`, `customs=0\|1` | ტრანსპორტირების / განბაჟების გადავადება |
| `method=bog\|tbc\|mere`, `term=N` | ბანკი და ვადა (თვეები) |
| `delivery=courier\|pickup` | მიწოდების მეთოდი |
| `details=1`, `info=weight\|customs\|all` | ფასის დაშლა გახსნილი / „დაახლოებითი თანხების“ ახსნა |
| `err=1` | ვალიდაციის შეცდომები (`#/register/verify`-ზე ასევე `err=wrong\|expired`) |
| `loading=1`, `processing=1`, `anim=0` | გაყინული ჩატვირთვა / გადახდის სპინერი / ანიმაციის გარეშე |
| `empty=1` | ცარიელი „ჩემი შეკვეთები“ |
| `auth=0` | გამოსვლა |
| `toast=1` | სანიმუშო შეტყობინება |
| `#/profile?demo=1` | პროფილი დემო მონაცემებით (პაროლი `slicepay1`; ნომერი 577 123 456 თავისუფლდება მხოლოდ მაშინ, როცა იქ QA-ს მიერ გადატანილი დემო ანგარიშია) |
| `&edit=phone`, `&edit=phone&step=code`, `&err=1` | ნომრის ფორმა გახსნილი / კოდის ეტაპი (კოდი `4821`, ნომერი 577 123 456) / შეცდომები |

სრული სია: `docs/ARCHITECTURE.md` („Supported QA params“, v4-ის დეტალები — „v4 integration → Routes and QA params
added in v4“) და `docs/INTEGRATION.md` (§4; v4 პროფილი — „What each engineer must do → Profile“ §5).

## Tests

```bash
npm install          # ერთხელ (Playwright 1.63.0; საჭიროების შემთხვევაში: npx playwright install chromium)
npm test             # ყველა სუიტი + დიზაინთან შედარება, ბოლოს pass/fail ცხრილი (საჭიროა python3 + Pillow)
npm run test:visual  # მხოლოდ დიზაინთან შედარება (საჭიროა python3 + Pillow)
```

- დიზაინთან შედარებას (ის `npm test`-შიც შედის) სჭირდება python3 და Pillow: `pip3 install pillow`. მათ გარეშე
  გაუშვით `npm test -- --no-visual`.

- ფილტრი: `npm test -- orders delivery`; შედარების გარეშე: `npm test -- --no-visual`.
- სხვა ასლის შესამოწმებლად: `APP_DIR=/path/to/copy npm test`. ფარდობითი `APP_DIR` / `TEST_OUT` გაიხსნება იმ
  საქაღალდიდან, საიდანაც runner ეშვება (`npm test`-ის დროს ეს პროექტის ფესვია); უსაფრთხოა აბსოლუტური გზა.
- შედეგები (სქრინშოტები, ლოგები, `summary.json`) იწერება `tests/out/`-ში (git-ში არ შედის).
- დიზაინთან შედარება 34 ეკრანს ადარებს Figma-ს ფრეიმებს (`tests/fixtures/frames/`) და შენახულ
  საბაზისო ქულებს (`tests/visual/baseline-scores.json`) დასაშვები გადახრით.

დეტალები: `tests/README.md`.
